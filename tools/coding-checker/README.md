# Локальная проверка CF-01

Необязательная практика на компьютере: проверяющий компилирует точный текст
экспортированной функции как C++23 и возвращает фактические векторы результата
и остатка для открытых случаев `TakePrefix`. Исправьте функцию по диагностике
или проваленному случаю, экспортируйте новую попытку и проверьте её снова.
Mini App не исполняет функцию и не отправляет её на сервер.

Требуются Python 3, уже работающий локальный Docker Engine под Linux с cgroup v2,
ограничениями памяти/CPU/процессов и стандартным seccomp, а также проверенный
локальный образ проверяющего. Скрипт не устанавливает программы, не запускает
Docker daemon, не собирает и не скачивает образы. Доступ к Docker даёт широкие
права: используйте инструмент только на своём компьютере для разработки.

Отдельно соберите необязательный образ из корня репозитория:

```sh
docker build -f tools/coding-checker/Dockerfile -t cpp-recall-local-checker .
docker image inspect --format '{{.Id}}' cpp-recall-local-checker
```

Для каждой попытки укажите полученный неизменяемый **локальный ID образа**:

```sh
python3 tools/coding-checker/check.py submission.json --report report.json --image sha256:<64-hex-image-id>
```

Параметр `--daemon-socket /run/user/1000/docker.sock` позволяет выбрать
существующий локальный Unix socket Docker в режиме rootless. По умолчанию
используется `/var/run/docker.sock`. Удалённые контексты и `DOCKER_HOST`
игнорируются. Docker socket и файлы компьютера не монтируются внутрь проверяющего.
Отчёт создаётся только в новом файле: для повторной проверки выберите другое имя.

Образ использует GCC 14.4.0 (C++23) из поддерживаемой официальной серии GCC.
Источник выбора версии — [манифест GCC в Docker Official Images](https://github.com/docker-library/official-images/blob/master/library/gcc),
проверенный 8 ноября 2026 года: он перечисляет `14.4.0-trixie` и срок поддержки
этой серии до 26 декабря 2027 года. Базовый тег указывает конкретный выпуск
компилятора. Сохраните и проверьте ID собранного образа: скрипт требует этот ID
и `--pull=never`, поэтому запуск не скачает образ и не переключится незаметно
на обновлённый тег. Вспомогательный образ отделён от образа приложения.

Каждая попытка получает отдельную временную файловую среду в контейнере с UUID
в имени: непривилегированный UID, отключённые capabilities и сеть, отдельные
пространства имён cgroup/PID, базовая файловая система только для чтения.
Рабочая tmpfs ограничена 64 MiB и разрешает исполнение; временная tmpfs — 16 MiB
с запретом исполнения. Лимиты: 384 MiB RAM без swap, один CPU, 32 процесса,
64 открытых дескриптора, 16 MiB на файл, отключённые core dumps, 35 секунд CPU
на процесс и 45 секунд общего времени. Компиляция проходит в той же ограниченной
среде за максимум 30 секунд; исполнению программы отводится 5 секунд.
Вывод компилятора/программы ограничен 64 KiB, передача результата — 128 KiB,
отображаемая диагностика — 16384 символами. Очистка затрагивает только контейнер
этой попытки, в том числе при отмене. При недоступности защит проверка прекращается;
запасного исполнения на компьютере вне контейнера нет. Безопасность зависит
от актуальности ядра и контейнерной среды; инструмент не предназначен для
публичной проверки кода множества пользователей.

Схема отправляемого файла: `cpp-recall-local-submission/v1`. Идентификаторы:
`take_prefix`, редакция `1`, набор `take_prefix-public-v1`. Поля:
канонический UUID `attempt_id`, точный текст `source` в UTF-8 до 16384 байт,
его `source_sha256` в нижнем регистре и объект `assistance` с логическими
`help_opened` и `solution_opened`. Экспортируйте JSON из Mini App,
не редактируя служебные поля.

Схема отчёта: `cpp-recall-local-check/v1`. Идентификаторы, хеш, попытка и признаки
помощи копируются из отправленного файла. `compiler` и `compile` всегда являются
объектами. После завершения исполнения `tests` содержит фактический вход
`input_pending`, векторы результата/остатка и отдельные сравнения для всех
открытых случаев. Статус `tests_passed` требует успешной компиляции, успешного
исполнения, полного набора ID случаев и совпадения результатов. Одного нулевого
кода возврата или напечатанного PASS недостаточно. Остальные статусы различают
ошибки компиляции, тестов, исполнения, лимитов времени/ресурсов/вывода,
недоступность изоляции и сбои проверяющего. CLI возвращает 0 для `tests_passed`,
1 для отчёта с другим статусом и 2 при некорректных входных данных или ошибке
работы с файлами. Отказ в разрешении на запуск бинарника получает `runner_error`:
он не означает, что программа ученика успела исполниться и завершилась ошибкой.

Каждый отчёт имеет `trust: local_unverified`. Хеш связывает его с черновиком,
но не доказывает происхождение или честность исполнения. Пользователь может
подделать JSON, а намеренно вредоносный C++ — имитировать данные проверяющего.
Успешные открытые тесты не доказывают отсутствие UB, корректность на всех входах,
самостоятельность, перенос навыка или его сохранение спустя время.
Импорт не даёт XP, выполнения задания дня или серверного прогресса.
Признаки помощи служат локальному учёту, а не доказательству самостоятельности.
Результаты компиляции и тестов следует отделять от оценки обучения.

Проверяющий записывает векторы в отдельный временный файл ограниченного размера.
Обычный отладочный вывод функции перехватывается с ограничением объёма
и не трактуется как вердикт. Неполные записи или ранний выход процесса
не дают успешного результата. Это разделение не является криптографической
защитой от намеренной подделки локальной попытки.

Запуск тестов скрипта и контракта на компьютере, без Docker и только
на доверенных авторских данных:

```sh
python3 tests/coding_checker_test.py
```

Для проверки реальной компиляции и ограничений изоляции нужны вспомогательный
проверенный образ и явный запуск контейнера. Отсутствие такого запуска
остаётся ограничением проверки и не считается успешным тестом изоляции.
