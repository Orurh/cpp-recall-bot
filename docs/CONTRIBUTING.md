# Как предложить карточку

Качество содержимого важнее количества. До редактирования банка прочитайте
[модель обучения](training_methodology.md) и [правила проекта](../AGENTS.md).
История рецензий на конкретные редакции находится в [реестрах](reviews/content/README.md).

## Сначала содержание

- Сформулируйте, какой навык проверяет вопрос и какие знания нужны до него.
- Сделайте условие однозначным. Для ввода кода явно укажите, требуется ли выражение,
  тип или полная строка с `return` и `;`.
- Объясните правило на показанном коде, а не просто повторите правильный ответ.
- Для спорных правил языка приведите применимую редакцию стандарта и раздел.
  Сборка примера не доказывает отсутствие UB или правильность нормативного вывода.
- При сомнении оставьте вопрос на обсуждение. Не подменяйте рецензию зелёным валидатором.

## Данные карточки

Вопросы находятся в [`content/questions`](../content/questions). Обязательные поля:
`id`, `public_id`, `topic`, `skill_id`, `question_family_id`, `evidence_type`,
`transfer`, `kind`, `level`, `standard`, непустой `tags`, `text`, `task`, `explanation`.
Начинайте с близкой по формату существующей карточки, но не копируйте её правильный
ответ или объяснение без проверки новой задачи.

Темы и навыки должны соответствовать действующим каталогам. Варианты одной проверки
знания сохраняют `question_family_id`: смена чисел или имён не делает пример независимым.

Номер `public_id`, например `CR-000123`, постоянный. Новая карточка получает номер
после максимального зарезервированного в
[`question_registry.json`](../content/question_registry.json). Номера удалённых
карточек не переиспользуются; перемещение файла и правка текста не меняют номер.

Пример поля `task` для сопоставления; это **не полная карточка**:

```json
{
  "type": "matching",
  "pairs": [
    {"id": "sort", "left": "std::sort", "right": "Сортирует диапазон"},
    {"id": "find", "left": "std::find", "right": "Ищет равный элемент"}
  ]
}
```

Поддерживаются от 2 до 6 пар. Интерфейс перемешивает колонки; ошибка увеличивает
счётчик попыток, но не завершает карточку.

## Перед pull request

```bash
make content-check
make content-audit
make content-coverage
python3 scripts/validate_content_reviews.py
```

Структурные проверки не заменяют техническую и педагогическую рецензию.
Если карточка уже включена в реестр проверенных редакций, содержательная правка
требует повторной проверки и обоснования, а не одного пересчёта контрольной суммы.
Публичные задания дополнительно закреплены по SHA в `src/miniapp/shared_challenge.h`.
Правка такой карточки отключает старую ссылку до явной рецензии и обновления каталога;
не обновляйте закреплённую редакцию только ради зелёного теста.
Не прикладывайте `.env`, токены, выгрузки базы, реальные отзывы и локальные дампы кода.
