# Диагностика повторных ответов (MEM-01)

Отдельный инструмент для владельца: считает наблюдаемые результаты по сохранённой
истории, не меняет обучение. В Mini App нового экрана нет. Это не персональная
модель памяти, аттестация, оценка переноса или основание для начисления опыта.

## Запуск на локальной копии данных

Нужны Python 3 и `psql`. Параметры подключения задаёт оператор обычными средствами
PostgreSQL; скрипты не читают `.env`, не устанавливают соединение из Python и не
выбирают сервер за пользователя. Используйте отдельную роль только для чтения.
Не запускайте на рабочей БД ради пробы: для проверки есть синтетические тесты.

Из корня проекта, в Bash:

```bash
set -o pipefail
psql -X -qAt -v ON_ERROR_STOP=1 -f scripts/export_retrieval.sql |
  python3 scripts/report_retrieval.py --pause-hours 24
```

SQL работает в согласованном снимке `REPEATABLE READ READ ONLY`, с ограничением
времени 10 секунд и завершением `ROLLBACK`. Он читает существующие попытки, события
помощи и архивы редакций, не создаёт таблиц и не выполняет миграции. Исходный текст
ответа и профиль Telegram не выгружаются. Промежуточный JSON содержит внутренние
ID пользователя/карточки: не сохраняйте его в Git и не отправляйте публично.
Итоговые агрегаты тоже являются рабочими данными, не материалом для публичного коммита.

Python читает JSON из stdin и печатает только агрегат в stdout. Сети, записи файлов,
SQL, API приложения или изменения прогресса в нём нет. При неправильном/неполном
входе — код 2 и пустой stdout, без вывода исходных записей. Успех — код 0.

## Что именно считается

Единица истории — пользователь + направление C++ + навык. Отсчёт промежутка идёт
от последнего **зарегистрированного** ответа любой карточки навыка или события
помощи по нему, включая неправильный ответ и помощь без последующего ответа.
Это не промежуток от входа в приложение, due date или присвоения `demonstrated`.

В `delayed.total` входят только первые попытки карточки (`attempt_number=1`),
без зарегистрированной помощи, с известной редакцией/навыком/семейством, известным
учётом помощи и наблюдаемым промежутком не меньше заданного. Начало промежутка
также должно быть не раньше старта наблюдения. Другая сессия сама по себе паузу
не доказывает, а предыдущая попытка может принадлежать другой карточке того же навыка.
Новый промежуток начинается после каждой относящейся к навыку записи.

При равном времени неизвестные события обрабатываются консервативно до оценки
ответа. Несколько ответов одного навыка в одно и то же время не позволяют надёжно
выбрать первый: они исключаются как недостаточная история, а не сортируются по ID
ради выбора верного/неверного исхода для знаменателя.

`outcomes` — непересекающиеся категории всех ответов: недостаточная разметка,
исправление, помощь, неизвестный учёт помощи, недостаточная история, первое
наблюдение, короткая пауза, отложенный верный/неверный ответ. `help_events` считается
отдельно. Несколько причин исключения могут относиться к одной попытке: выводится
первая по указанному порядку, не число всех возможных причин.

`delayed.correct_percent` — верные / все допустимые отложенные первые ответы,
а не процент знания. При пустом знаменателе — `null`. Отсутствие возвращения
пользователя не добавляет ни ошибки, ни успеха. Случайная ошибка не объявляется
полной утратой навыка и не меняет его состояние.

У допустимых наблюдений отдельно показаны:

- `familiar_card` — уже встреченная карточка той же редакции;
- `changed_revision` — знакомый ID, но другая редакция;
- `family_variant` — другой ID знакомого семейства;
- `other_family_unverified_context` — ещё не встреченное семейство; новизна
  контекста **не подтверждена** и не выводится из нового ID/семейства;
- тип разметки задания: `recognition` или `application`. Это не доказательство
  самостоятельного написания программы, воспроизведения принципа или переноса.

`observed_until`, `tracking_since` и `minimum_pause_hours` сохраняют параметры
расчёта. 24 часа — исходный фильтр отчёта, не научно установленный оптимум памяти.
Допустимы целые пороги 1–720 часов; интервалы приложения при этом не меняются.

## Ограничения истории

Экспорт привязывает разметку к архиву отвеченной редакции, не к текущему банку.
Пустую старую редакцию и неизвестную помощь нельзя задним числом сделать чистыми.
Для отрицательного флага помощи требуется соответствующее сохранённое событие
ответа; до `tracking_since` отсутствие помощи неизвестно. Положительная помощь
всегда исключает самостоятельную попытку. Событие с неизвестным навыком мешает
надёжно установить промежуток для этого пользователя и учитывается консервативно.

Отчёт описывает только **сохранившиеся зарегистрированные действия**. Повторные
открытия помощи внутри одной карточки/сессии не дают новых событий с точным временем;
старые события могли быть удалены по политике хранения. Поэтому промежуток между
сохранившимися записями не доказывает отсутствия промежуточного обучения. Просмотр
другой справки, внешние материалы и запоминание ответа также не контролируются.
Это диагностические кандидаты для проверки, а не подтверждённая оценка памяти.

Для System Design нет сопоставимого журнала времени каждого ответа/открытия помощи:
`system_design=not_assessed`. Сохранённое состояние и самооценка не превращаются
в C++-наблюдения. Его собственная диагностика требует отдельного решения об учёте.

Экспорт ограничен 50000 событиями, JSON — 16 MiB. Превышение отклоняет расчёт,
а не выдаёт частичный знаменатель. `complete` подтверждает отсутствие обрезания
этим лимитом, **не** полноту исторического учёта. Ручной входной JSON можно подделать;
этот инструмент не является защищённой аттестацией и не влияет на XP/освоение.

## Проверка

```bash
python3 tests/retrieval_report_test.py
```

SQL-интеграция использует только локальную одноразовую `TEST_DATABASE_URL` и
временные таблицы; без неё тест возвращает 77, а не заявляет успешный SQL-прогон:

```bash
python3 tests/retrieval_report_sql_test.py
```

Сценарии выбора повторения/восстановления описаны в
[методике](training_methodology.md#приоритет-восстановления-mem-02). Отчёт не управляет
этим выбором и не заменяет расписание, пропорцию 6/4 или пороги освоения.
