# C++ Recall Bot

Telegram-тренажёр для повторения C++. Бот подбирает сложность отдельно по темам,
возвращает ошибки в конец тренировки до правильного ответа и планирует последующие повторения по
истории ответов. Попытки и прогресс хранятся в PostgreSQL.

Качество учебного материала важнее размера банка. Спорные утверждения проверяются по стандарту C++; автоматическая
проверка структуры карточек не заменяет техническую рецензию. Подробные правила описаны в
[`docs/training_methodology.md`](docs/training_methodology.md).

## Возможности

- режимы «Теория», «Библиотека C++ (API/STL)» и «Код»;
- выбор одной, нескольких или всех тем перед тренировкой;
- выбор любой открытой ступени сложности в мини-приложении; более сложные ступени заблокированы;
- одиночный, множественный, короткий ответ и сопоставление;
- адаптивный уровень пользователя и каждой темы;
- каталог конкретных навыков с проверяемыми зависимостями и привязкой каждого вопроса;
- интервалы повторения 1, 3, 7, 14 и 30 дней;
- цикл исправления: неверная карточка возвращается после новых, пока не будет исправлена;
- теоретический разбор после ошибки для пилотного модуля «Время жизни и RAII»;
- атомарная и идемпотентная запись ответа;
- отдельный журнал опыта (XP) с защитой от повторного начисления за одно семейство вопросов;
- главный экран с быстрым стартом, ближайшей наградой и отдельной свободной настройкой тренировки;
- вкладка достижений с полным списком наград, автоматической выдачей прошлых порогов, рамками профиля и
  сохраняемыми наборами тренировок;
- статистика по темам, точности и повторениям по команде `/stats`;
- 172 вопроса в JSON с автоматической проверкой структуры;
- первый учебный модуль «Время жизни и RAII»: 40 вопросов по четырём связанным навыкам;
- 42 вопроса по ООП: от объектов и инкапсуляции до статического и динамического полиморфизма;
- отдельные блоки по библиотеке C++ (API/STL), шаблонам, атомарным операциям и асинхронным задачам (`std::async`/`future`);
- отдельный прогресс по навыкам, не смешанный с адаптивной сложностью.
- постоянные номера карточек и отзывы с сохранением исходной редакции, закрытая очередь редактора.

### Карточки сопоставления

JSON-карточка `matching` содержит от 2 до 6 пар:

```json
{
  "type": "matching",
  "pairs": [
    {"id": "sort", "left": "std::sort", "right": "Сортирует диапазон"},
    {"id": "find", "left": "std::find", "right": "Ищет равный элемент"}
  ]
}
```

Мини-приложение показывает две перемешанные колонки. После правильной пары оба элемента
исчезают; ошибка увеличивает счётчик, но не завершает карточку.

## Быстрый запуск

Нужны CMake 3.28+, компилятор с C++23, PostgreSQL и библиотеки Boost.JSON,
Boost.System, libcurl, libpq и spdlog.

```bash
cp .env.example .env
# Укажите TELEGRAM_BOT_TOKEN и замените пароль в .env.
docker compose up -d postgres
make run
```

`make run` загружает переменные из `.env`. При старте приложение автоматически
применяет SQL-файлы из каталога `migrations/`.

Для запуска приложения и базы целиком в контейнерах:

```bash
cp .env.example .env
# Заполните TELEGRAM_BOT_TOKEN и POSTGRES_PASSWORD.
docker compose up --build -d
docker compose logs -f bot
```

Порт PostgreSQL публикуется только на `127.0.0.1`. Если `5432` занят
другим проектом, задай в `.env`, например, `POSTGRES_HOST_PORT=5433`.

## Мини-приложение Telegram (Mini App)

Полная тренировка доступна в мини-приложении: выбор сложности и тем, все типы вопросов, серверная
проверка ответов и синхронизированный PostgreSQL-прогресс. При заданном `MINI_APP_URL` бот
автоматически настраивает кнопку меню. Команды `/start` и `/menu` также отправляют кнопку мини-приложения.
Прохождение карточек непосредственно в чате не поддерживается.

Настройка HTTPS, reverse proxy и BotFather: [`docs/MINIAPP_SETUP.md`](docs/MINIAPP_SETUP.md).

Закрытая статистика беты, проверки доступности, оповещения и проверяемые резервные копии:
[`docs/BETA_MONITORING.md`](docs/BETA_MONITORING.md).

Состояние проекта и следующая задача: [dashboard.md](dashboard.md).
Проектные правила и роли: [AGENTS.md](AGENTS.md), [agents/README.md](agents/README.md).

Автор и связь по содержанию карточек: Артём Шеленко, [artem.shelenko@gmail.com](mailto:artem.shelenko@gmail.com).

Для временной сквозной проверки через GitHub Codespaces добавь секрет Codespaces
`TELEGRAM_BOT_TOKEN`, создай Codespace и выполни:

```bash
./scripts/run_codespace.sh
```

Скрипт вычислит публичный HTTPS URL, запустит Compose и попытается открыть порт
8080. Codespaces переводит публичные порты обратно в закрытый режим после перезапуска, поэтому скрипт
нужно запускать заново при каждом старте Codespace.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен бота от BotFather |
| `DATABASE_URL` | PostgreSQL URI для локального запуска |
| `DATABASE_POOL_SIZE` | число общих соединений с PostgreSQL, по умолчанию 5 |
| `MINI_APP_FEEDBACK_ADMIN_ID` | числовой Telegram ID владельца закрытой очереди отзывов; пустое значение закрывает доступ |
| `POSTGRES_DB` | имя базы в Docker Compose |
| `POSTGRES_USER` | пользователь базы в Docker Compose |
| `POSTGRES_PASSWORD` | пароль базы в Docker Compose |

## Проверки

```bash
make check          # сборка, контент, модульные тесты, формат и cppcheck
make test           # CTest; storage-тест пропускается без TEST_DATABASE_URL
make content-check  # проверка всех JSON-вопросов
make content-audit  # редакционные эвристики без подсказок длиной ответа
make format         # применить clang-format
make tidy           # отдельная строгая проверка clang-tidy
```

Интеграционный тест PostgreSQL можно запустить так:

```bash
TEST_DATABASE_URL="$DATABASE_URL" ctest --test-dir build \
  --output-on-failure -R 'storage_tests|miniapp_feedback_tests'
```

Сквозная проверка отзывов в Chromium (Node.js 22+; только на отдельной тестовой базе):

```bash
TEST_DATABASE_URL=postgresql://user:password@localhost/test_db node tests/browser_feedback_smoke.mjs
```

Проверка использует тестовый токен, локальный сервер и заблокированные внешние подключения. Она проверяет мобильную
форму, потерю ответа после сохранения, повторную отправку, очередь владельца и отказ в доступе другим пользователям.

## Структура

- `src/app` — сценарий тренировки и адаптивный выбор;
- `src/bot` — длительный опрос Telegram (long polling), точка входа мини-приложения и статистика;
- `src/learning` — очередь повторных попыток и состояние повторения;
- `src/storage` — загрузка контента и PostgreSQL;
- `content/questions` — банк вопросов;
- `docs/reviews/content` — реестры проверки редакций, не данные приложения;
- `migrations` — версионируемая схема базы;
- `tests` — модульные и интеграционные тесты.

Каждый вопрос обязан содержать `id`, `public_id`, `topic`, `skill_id`, `question_family_id`,
`evidence_type`, `transfer`, `kind`, `level`, `standard`, непустой `tags`, `text`, `task` и
`explanation`. Команда `make content-check` проверяет тему и навык по каталогам, тип задания,
варианты ответа, диапазон уровня, целостность семейств и уникальность `id`. Каталог тем и их
пользовательские названия находится в
`src/quiz/topic_catalog.h`.

`public_id` имеет вид `CR-000123` и проверяется по постоянному реестру `content/question_registry.json`.
Записи удалённых карточек из реестра не удаляются, номера не переиспользуются. Новая карточка получает следующий
номер после максимального зарезервированного; перемещение файла или правка текста не меняют номер.

Правила попыток, адаптивного уровня, интервальных повторений и метрик описаны в
[`docs/training_methodology.md`](docs/training_methodology.md).
Порядок следующих учебных функций зафиксирован в
[`docs/LEARNING_ROADMAP.md`](docs/LEARNING_ROADMAP.md).

Устройство, ограничения, остановка и повтор выпуска — в [AUTO_DEPLOY.md](docs/AUTO_DEPLOY.md).
