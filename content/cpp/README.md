# Учебный контент C++

Направление → тема → навык → уровень → материалы → практика → повторение.
Это представление существующих каталогов, а не второй учёт прогресса.

- `curriculum.json`: цели десяти уровней пилота «Контейнеры», правило продвижения.
  У остальных тем пока честно обозначен каталог практики, не готовый учебный путь.
- `topics/<topic>/skills/<skill-id>/materials*.json`: теория, справки и точные связи.
  Существующие skill IDs, зависимости и названия проверяются по `SkillCatalog`.
- `content/questions/` и `content/question_registry.json`: единственный банк заданий
  и постоянные публичные номера. Не копируйте вопросы в учебный каталог.

## Схема материалов

Корень содержит `schema_version: 1`, `skill_id`, `theory`, `references`,
`theory_bindings`, `reference_bindings`. Пустые массивы допустимы. У статьи:
`catalog_order`, `id`, `title`, `principle`, `mechanism`, `example`,
`common_mistake`, `sources`, `source_kind`; у теории также `primary`.
Порядок сквозной и непрерывный для каждого каталога; ID уникальны.

Теория связывается явно с `question_family_id` и `theory_id` внутри навыка.
Справка — с точными `question_id`, `content_revision`, `reference_ids`.
Непроверенная редакция не наследует статью. Первичная теория применяется только
к явно обозначенному навыку; совпадения по тегам или названию не используются.
Общий материал хранится один раз; ссылки могут использовать его из других навыков.

## Сборка и проверка

`scripts/generate_learning_content.py` проверяет схему, типы, порядок, неизвестные
поля/ID и связи; CMake генерирует типизированные статические C++ массивы.
Сборка требует Python 3, работа приложения — нет. Runtime не читает эти JSON
и не зависит от пути репозитория. Изменение/добавление файла запускает генерацию.
`curriculum.json` встраивается при конфигурации; `content_check` проверяет его
схему и владельцев вопросов. Невалидный учебный каталог не проходит проверки.

Тесты `learning_catalog_equivalence` закрепляют старые канонические снимки
15 теорий, 41 статьи и всех исторических связей. Не пересчитывайте базовый
хеш ради зелёного теста. Новое содержание оформляется отдельной рецензией;
намеренные изменения старой карточки/выбранной теории перечисляются точечно.

## Разделы и прогресс

Стабильный раздел `cpp.<skill_id>.l<level>` выводится из реальных вопросов навыка
и сложности. API возвращает цель уровня, предпосылки, семейства, материалы,
источники, решённые карточки и повторы. Не передаёт правильные ответы.
Сервер сам выбирает задания раздела и проверяет предел сложности/предпосылки;
клиент не может подменить темы или план. Повтор старого запроса восстанавливает
сохранённую тренировку, а новая тренировка не удаляет предыдущую.
После снижения рабочей сложности знакомые задания не закрываются: сервер
оставляет их в практике, но не подмешивает ещё не изученные сложные задания.
Поиск исходной сессии по UUID предшествует проверке допуска к новой тренировке.
Добавленные позднее карточки не изменяют её исходную очередь и отметки помощи.

Материалы вне задания — подготовка без XP/mastery. Если семейство или статья
совпадает с текущим либо будущим заданием активной/отложенной тренировки,
сервер предлагает продолжить её и воспользоваться учитываемой справкой.
Состояния навыков и интервалы остаются прежними. System Design не меняется.

Покрытие — структурная оценка. Три ID не доказывают три независимые проверки,
а ограниченное мини-ревью L9/L10 не доказывает свободное написание реализации
или долговременное освоение. Для этого нужны отдельные наблюдения после паузы.
